## 헤비한 이슈 (구현 전에 풀거나 위험으로 안고 가야 함)

### H-1. 4.4MB 상한에서 담을 수 있는 녹음 길이가 포맷마다 크게 다르다
- 길이 제한(60초)은 폐기했으므로(D-009) 서버는 길이를 재지 않고 **용량(4.4MB)만** 본다.
- 4.4MB 는 mp3 128kbps 로 약 4분 35초, 22.05kHz 모노 wav 로 약 1분 40초, 44.1kHz 스테레오 wav 로는 약 25초다. wav 로 녹음한 사용자는 짧은 파일도 413 을 만날 수 있다.
- 화면의 413 문구에 "mp3 권장" 같은 안내를 둘지는 spec 작성 때 정한다.

### H-2. Vercel 함수 시간 제한 안에 Gemini 호출이 들어가야 한다
- 받아쓰기(`POST /api/upload`) 와 회의록 저장(`POST /api/teams/{id}/meetings`) 이 각각 Gemini 를 부른다. Vercel 함수의 기본 실행 시간 제한이 짧아서 설정 없이는 시간 초과가 날 수 있다.
- 두 호출 모두 Vercel 의 최대 실행 시간 설정이 필요하다. 구체적인 제한값은 구현 전에 Vercel 문서로 확인한다 (이 기록은 기억에 의존한 것이라 값을 적지 않았다).
- 시간 초과가 나면 화면에서 보일 상태는 스토리보드 C 에도 없다. 오류 코드 집합(D-012)을 늘리지 않고 어떻게 표시할지 정해야 한다.

### H-2 보충. 실측 시간 (로컬, 2026-10-08)
- 시험 wav(99.6초, 4.39MB) 받아쓰기 3.7초, 그 본문 정리 2.7초. 로컬에서 본 값이며 배포 환경의 함수 실행 시간 제한과는 별개다. 배포 보류 중이라 제한 확인은 미뤄 둔다.

### H-3. 업로드 상한의 근거 (해결, 운영 실측)
- 상한 근거는 Vercel 함수 요청 본문 한도(공식 문서 4.5MB, 모든 요금제 공통, 초과 시 413 `FUNCTION_PAYLOAD_TOO_LARGE`)다. 2026-10-08 운영 배포에서 실측했다.
- **실측 결과**: 가짜 wav 로 이분 탐색하니 파일 4,492,247 바이트는 통과, 4,493,935 바이트는 플랫폼이 413 을 돌려줬다(공식 4.5MB 에 폼 경계 · 헤더가 더해짐). 플랫폼의 413 은 JSON 이 아니라 `Request Entity Too Large  FUNCTION_PAYLOAD_TOO_LARGE` 글자라서, 서버 상한을 그 아래인 4,400,000 바이트로 두어 우리 코드가 먼저 `PAYLOAD_TOO_LARGE` 를 돌려주게 했다. 4.4MB 로는 시험 파일(4.39MB)이 통과한다.
- 25MB 에서 낮추면서 spec 에서 바뀐 곳: ACME 의 Constraints (업로드 25MB), C-09 의 413 문구, 범위 외의 "25MB 초과 분할 업로드 안 함", `publish/detail.html` 의 댓글 예시 문장("25MB 제한은 녹음 40분쯤"). 마지막은 모의 데이터라 구현 때 새로 썼다.

### H-4. 기한 입력과 판정 방식 (차후 논의로 미룸)
- 이번 회차는 `publish` 대로 구현한다. `todos.html` 은 기한 배지를 누를 때마다 "미정 · 오늘 · 이번 주 안 · 다음 주 금요일 · 어제 · 지난 주" 를 순환하고, 어제 · 지난 주 · 지난 달 만 붉은 띠로 판정한다.
- 알려진 한계: `due_text` 가 자유 글자라 "다음 주 금요일" 은 시간이 지나도 계속 같은 글자이고 붉은 띠가 켜지지 않는다. 실제 날짜 비교는 `YYYY-MM-DD` 값에서만 가능하다.
- 차후 논의 거리: 기한을 날짜로 입력하게 할지, Gemini 가 `met_at` 기준 날짜로 바꿀지, 지난 표현 목록을 어떻게 다룰지. 정해지면 D-003 · D-011 을 갱신한다.

### H-5. 내 정보 수정의 현재 비밀번호 칸 (해결됨, D-024)
- 프로그램정의 7-4 는 비밀번호 변경 때 현재 비밀번호를 함께 받으라고 하는데, 확정 퍼블리싱(`profile.html`)과 스토리보드 J 에는 그 칸이 없었다.
- 사용자가 "비밀번호 받는 화면은 우리가 생성한다" 로 정했다. 구현에서 칸을 추가한다.
- 남은 일: `publish/profile.html` 과 스토리보드 J 가 구현과 달라지는 점을 이슈보고(R-01)에 올려 차후 보고한다.
